# 哈基米 (Hachimi) 功能代码参考指南

本文档记录了 Bilibili Discord 机器人的特定内置功能：哈基米 (Hachimi) 功能的设计原理和代码实现。

## 1. 概述

哈基米功能是一个自动化命令，会在 Bilibili 上自动执行“哈基米”的视频检索，通过内部特定的质量判断过滤结果，将最顶级的几个优质结果加入机器人的播放队列中自动播放。

## 2. 命令与权限

**命令：** `/hachimi`

**描述：** 自动播放 5 个符合内部数据量门槛的带有“哈基米”内容标签的 B 站视频。

**权限拦截机制：**
- 拦截器：触发用户必须处于一个 Discord 语音频道内。
- 机器人权限配置：机器人需拥有 `Connect` 及 `Speak` 权限才能响应成功。

## 3. 过滤算法的核心逻辑

该功能代码通过一个智能过滤算法来筛选高点赞和高曝光率的视频。当视频在响应返回时，需要符合以下**任意一条**标准：

1. **高互动率（High Engagement）：** 点赞率 > 5% （点赞数 / 播放量 > 0.05）
2. **高播放热度（High Popularity）：** 播放量 > 10,000 次

机器人发送 API 请求获取基础结果集，对候选集应用上述过滤后截取符合逻辑的前 **5 个** 视频。

## 4. 技术实现与路径层

### 4.1 代码结构依赖
- `src/bot/commands/hachimi.js`：Discord.js 原生 Slash Command（斜杠命令）入口注册与事件响应器。
- `src/utils/bilibiliApi.js`：包含 B站 API 请求核心逻辑、检索接口和视频过滤器。

### 4.2 模块的业务流程梳理
1. 用户执行斜杠命令 `/hachimi`。
2. Bot 执行语音连接与会话状态的前置有效性校验 (Validation)。
3. 会话服务透传调用 `BilibiliAPI.searchHachimiVideos(5)`：
   - API 执行分页搜索请求查询关键词“哈基米”（通常为了确保数量足够会单次请求提取 50 个预备视频作为候选）。
   - API 使用函数 `filterQualityVideos` 解析这 50 个预备视频的数据层。
   - 返回最高质量的 5 个视频结构对象。
4. Bot 触发 `QueueService` 清空目前所有的待播列表防止冲突。
5. Bot 将解析完成的 5 个 B站原始播放地址注入到 `PlaylistManager` 或对应的内存音频队列控制器内。
6. 调用 `AudioPlayer` 开始自动状态机流播放。

## 5. 常量配置项设置

这部分功能受 `src/utils/bilibiliApi.js` 与命令处理文件中的内部常量约束：

- **搜索请求关键字词 (Search Query)：** `"哈基米"`
- **成功回传数量限制 (Max Results)：** `5`（默认上限）
- **单次提取阈值 (Fetch Limit)：** `50` （防止视频未达到质量而不够提取）
- **质量分要求 (Quality Thresholds)：**
  - 最低点赞率：`0.05` (5%)
  - 最低播放量：`10,000`

## 6. 异常状态处理

- **无结果抛异常 (No Results Found)：** 当第一批 50 候选内甚至都没有达到阈值的视频时抛出。
- **提取器错误 (Extractor Error)：** 视频解析器引擎未成功拉取源音频流。
- **超时异常 (Timeout)：** 单次请求时间等待过长。
