## Summary

Fixes slow YouTube playback (the headline bug) and lands three internal refactors that remove duplication across the playback, extractor, and button-handling layers.

Net **+520 / −1030 lines** across 17 files, while adding two new utilities and a test suite. Verified: ESLint, `tsc --noEmit`, **603/603 tests**, `npm run build` — all green.

## Why YouTube was slow

1. **Pre-extraction was a silent no-op outside one test guild.** `prewarmYouTubeUrls` was gated by `isTestGuild`, so in every real server the warm cache never populated and playback always paid the full cold yt-dlp cost.
2. **Extraction ran yt-dlp's nsig JS-decipher path** (`--js-runtimes node`), the dominant per-extraction latency.

## Changes

### `perf(youtube)` — make pre-extraction effective + skip nsig JS decipher
- Ungate `prewarmYouTubeUrls` — runs wherever YouTube pre-extraction is enabled, matching Bilibili.
- New `YOUTUBE_PLAYER_CLIENT` env (default `tv,ios`): `--extractor-args youtube:player_client=tv,ios` returns pre-signed stream URLs, so yt-dlp skips downloading + executing the player JS. `--js-runtimes node` only used when the client list is explicitly emptied (bot-detection fallback).
- Add `--no-playlist` to single-video invocations.

### `refactor(playback)` — share concurrent extract+join; centralize resume-from-newest
- New `playback/extract_join.ts` owns the concurrent extraction + voice-join scaffolding (stage reporting, per-phase timing, settle-without-losing-error, leave-on-failure-from-idle) that was copy-pasted in the Bilibili and YouTube paths.
- Move the "resume from the newest track after a queue naturally ended" fix into `AudioPlayer.playNext()` — it was previously inlined only in the Bilibili path, so the YouTube path silently replayed `items[0]`. Now both behave correctly.
- Remove dead `playExtractedTrack()`.

### `refactor(extractors)` — extract shared ExpiringCache
- New unit-tested `utils/expiring_cache.ts` (TTL + max-size, lazy read eviction, unref'd cleanup, `dispose()`). Both extractors now use it; their bespoke cleanup methods, expiry/size fields, timers, and `{data,timestamp}` wrapper interfaces are gone.

### `refactor(buttons)` — centralize button→action mapping
- `PlayerService.handleButtonInteraction` is now the single source of truth; the near-identical duplicate switch in `AudioManager` is deleted. AudioManager intentionally kept as the per-guild player factory (full collapse deferred — `getPlayer` carries a critical extractor injection and isn't worth the blast radius).

### `chore(tests)` — drop stale references
- Remove a vestigial mock + assertion from `radio_interaction_guard.test.js`.
- Delete `tests/integration/test-all-features.js`: an orphaned manual harness, wired to no runner and broken against the current architecture since the DI refactor.
